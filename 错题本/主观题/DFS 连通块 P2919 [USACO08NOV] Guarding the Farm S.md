# DFS 连通块 P2919 [USACO08NOV] Guarding the Farm S

- 题目链接：https://www.luogu.com.cn/problem/P2919
- 题型：DFS / 连通块 / 图论
- 结论：本题本质上是统计每个“高点能向外扩展并与相同高度连通”的块数；枚举邻格时应限制在棋盘范围内，不要依赖数组填充值代替边界判断。

## 思路

- 先遍历每个格子，判断它是否存在至少一个相邻格子高度更高。
- 若存在，则从这个点开始跑 DFS，把和它相同高度、可相连的区域全部标记为已访问。
- 最后未被访问到的格子个数，就是答案。

这实际上是在用“等高连通块”来建图：只要相邻格子高度相同就连边；而每个局部峰值处开始扩展，能把整个可达等高块标记出来。

## 错点

### 1. `dfs` 中没有边界判断

原始写法：

```cpp
if (h[x + dir[i].first][y + dir[i].second] == h[x][y])
    dfs(x + dir[i].first, y + dir[i].second);
```

当 `x + dx` 或 `y + dy` 出现 `0`、`n+1`、`m+1` 等情况时，代码会访问棋盘外的坐标。当前 `h` 是大小为 `702 x 702` 的全局数组，在 `n, m <= 700` 时这些坐标仍落在数组分配范围内，并读取到零初始化的填充格，因此不能简单说这段访问本身就是越界 UB。

但填充格不属于棋盘。若棋盘边界上的高度也为 `0`，DFS 可能把填充格当成相同高度继续扩展，甚至继续访问数组范围之外。显式检查坐标能正确限定图的顶点范围，也不依赖高度值域和数组预留方式。

### 2. 把零初始化的填充格当作边界判断的替代

全局数组会被零初始化，因此当前坐标落在预留填充格时读到 `0` 是有保证的；但这不代表棋盘外的格子可以参与连通性判断。若填充值与合法格子的高度相同，DFS 就可能错误扩展。应先判断邻格是否在 `[1, n] x [1, m]` 内，再读取高度。

### 3. 主循环判断 `>` 时也需要判断边界

这部分也应显式判断边界：

```cpp
if (nx < 1 || nx > n || ny < 1 || ny > m) continue;
if (h[nx][ny] > h[i][j]) flag = true;
```

它防止相邻格子超出矩阵范围，避免访问到不合法位置。

## 关键结论

- `>` 判断和 `==` 判断都应先检查坐标是否属于棋盘。
- 额外分配的零值边界只能在明确验证坐标范围和高度值域后作为哨兵使用；显式判界更直接，也能避免 DFS 进入填充区域。
- 正确判断：要保证所有访问的坐标都在 `[1, n] × [1, m]` 之内。
- 复杂度：每个格子最多被访问一次，时间复杂度 `O(n * m)`，每次最多检查 8 个方向，整体约 `O(n * m)`。

## 复盘感悟

这道题最容易忽略的点，不是算法本身，而是“边界条件的正确性”。预留数组空间可能暂时掩盖棋盘外访问；方向枚举时仍应先判边界，确保 DFS 只在题目定义的格子上扩展。
