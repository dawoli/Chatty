区间DP / 状态语义

**题意**：N ≤ 248 个数，每次只能合并**相邻且相等**的两个数 x, x → x+1，求最终能得到的最大数。

**思路**：
- dp[i][j] = 区间 [i, j] 能否**整段合并成一堆**，能则为那一堆的值，否则为 0（死状态哨兵）。
- 转移：dp[i][j] = max{ dp[i][k] + 1 | dp[i][k] == dp[k+1][j] 且 != 0 }。
- 答案 = max{ dp[i][j] }（最优解不一定用完整个 [1, n]，比如末尾留个孤立大数）。

**错点**（49pts 版，WA）：
- 把 dp[i][k]、dp[k+1][j] 也放进 max 里"继承"，dp[i][j] 的语义从"整段合并成一堆"
  退化成"[i,j] 内任取子段的最大值"，一个数组混两种语义。
- 后果：合并条件 dp[i][k] == dp[k+1][j] 失效——相等的值可能来自**不相邻的散数**，
  被强行"隔空合并"。
- 反例 `3 1 1 3`：中间 1+1→2 后成 `3 2 3`，两端 3 永不相邻，答案 3；
  错解中 dp[1][1]=3（左端孤立 3）与 dp[2][4]=3（继承自右端孤立 3）"相等"，
  输出 4。
- 次要坑：ans 初始化要用 max{dp[i][i]} 而非只输出 dp[1][n]——整段可能合不成一块
  （`2 1 1 9` 整段死状态，答案是末尾孤立的 9）。

**关键结论**：
- 区间 DP 的合并条件 `dp[i][k] == dp[k+1][j]` 隐含要求**状态语义唯一**：
  dp[i][j] 必须严格表示"[i,j] 整段合并的结果"，否则相等值不代表"两堆真拼上"。
- "不可行状态"要么用 -INF/0 哨兵明确标记并在转移时排除，要么绝不让它参与继承；
  语义混用是区间 DP 最隐蔽的错误来源。
